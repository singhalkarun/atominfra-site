Private cloud machines

Your own machines, for you and your coding agent.

atominfra gives you a private Lane of virtual machines: Boxes you SSH into and GitHub Actions runners for your repos, all driven by one CLI, af.

Get started How it works
Install: npm install -g @atominfra/af
$ af box create dev --size S --json
{ "ok": true, "data": { "created": true, … } }
$ af box ssh dev
# you're in. Snapshotted nightly, 7 days kept.

$ af runner create ci --size CI --json
$ echo "$TOKEN" | af runner register ci --token - \
    --url https://github.com/you/repo --json
# token on stdin: used once, never stored

$ af doctor --json
{ "ok": true, "data": { "healthy": true, … } }

Everything you need to build, nothing you can't trust.

Two kinds of machine in one private Lane, managed the same way whether you type the command or your agent does.

›_

Boxes

Linux VMs you reach over SSH, for development, long jobs and agents. Snapshotted every night, with 7 days kept, and restorable in one command.

▶

Runners

Self-hosted GitHub Actions runners for your own repos, with a persistent cache. Keep one around or make it ephemeral for a single job. You register it with your own GitHub; af never holds the token.

◎

A private Lane

Everything you create lives in your Lane. Nobody else can see or reach it, it is reachable only from your own devices over a private network, and isolation between Lanes is audited.

Built to be driven by coding agents.

Claude Code, Codex and others run af under your user, with exactly your Lane's rights and no more. Give your agent one line:

Read https://docs.atominfra.com/llms.txt and use af to manage my machines.

The whole docs site is published as llms.txt, llms-full.txt and llms-small.txt, and the same guide ships inside the npm package.

  • Stable JSON everywhere. Every command takes --json; errors carry a code and what to do about it.
  • Safe to retry. Creating a machine that already exists returns it, so a timeout never makes a duplicate.
  • Hard to break things. Deleting a Box needs --confirm <name>. A Box holds your work.
  • Secrets stay with you. Tokens go in on stdin, are used once, and are never stored. The agent never holds your GitHub credential.
  • Knows when to upgrade. version.json tells an agent whether its af is current, and whether it must upgrade.

Sizes that fit the job.

CPU and RAM grow and shrink. Disk only grows. Your Lane has its own cores and caps on RAM, disk and machines, and every cap can be raised.

CI is a size for Runners only, sharing your Lane's CPUs.

What af will never do.

Promises, not settings.

  • Show you, or let you reach, another Lane.
  • Hold your GitHub token or any other credential.
  • Open a public port. Your machines reach the internet; the internet doesn't reach them.
  • Pretend snapshots are backups. Keep your work in git and pushed.
